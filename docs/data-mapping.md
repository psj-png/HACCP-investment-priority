# 데이터 매핑 설계 기록

## 개요

식품군별 HACCP 투자 우선순위 스코어를 산출하려면, 서로 다른 기관·형태의 데이터를 **품목유형** 기준으로 조인해야 한다. 이 문서는 데이터 탐색 과정에서 발견한 문제와 해결 방법, 그리고 매핑 실행 결과를 기록한다.

## 2. 조인 키: 품목유형명

CSV 파일 간 조인 키는 "품목유형명"이지만, 표마다 표기가 다르다.

### 표기 차이 예시

| 1-2-1-2 (생산) | 1-3-1-1 (위반) | 1-4-3 (수거검사) | 1-1-1-2 (업체) |
|---|---|---|---|
| 과자류, 빵류 또는 떡류 | 과자류, 빵 또는 떡류 | 과자류, 빵류 또는 떡류 | 과자류, 빵류 또는 떡류 |
| 유가공품류 | 유함유가공품 | 유가공품류 | 유가공품 |
| 식육가공품 및 포장육 | 식육함류가공품 | 식육가공품 및 포장육 | 식육가공품 및 포장육 |
| 기타식품류 | 기타식품류1) | 기타식품류 | 기타식품류 1) |

### 해결 방법

문자열 치환으로 통일. "빵" → "빵류", 후행 주석("1)") 제거, 영문 제거 등 전처리 후 매칭.

## 3. 핵심 문제: HACCP 인증 데이터의 품목유형 매핑

### 문제

Vulnerability(취약도) 산출에는 "식품군별 HACCP 인증 업체 수"가 필요하다. 식약처 CSV(1-5-2)에서 이를 제공하지만, 분류 체계가 다른 표와 일치하지 않는다.

1-5-2는 의무적용 품목(배추김치, 어묵류 등 16개)을 세부 단위로 나열하고, 자율적용 품목은 "기타 품목 5,996건"으로 합산 → 전체의 54%가 품목유형 미분류.

```
CSV 표 (1-2-1-2 등):  "수산가공식품류" = 1행
1-5-2 HACCP 표:        "냉동수산식품" 1,077건
                       "어묵류" 105건
                       "어육소시지" 16건
                       → 합치면 수산가공식품류에 대응하지만,
                       나머지 15개 품목유형은 "기타"에 매몰
```

### 해결

HACCP 인증업체 API를 사용. 이 API는 업체 1건마다 개별 품목코드(`businessitem`)를 제공한다.

품목코드 API에서 각 코드의 상위 카테고리(`pcd`)를 조회하면, 식약처 CSV의 품목유형과 동일한 단위로 집계할 수 있다.

---

## 4. API 필드 구조

### HACCP 인증업체 API 응답 (1건)

주의: `returnType=json`을 지정해도 이 API는 **XML로 응답**한다. `xml.etree.ElementTree`로 파싱해야 한다. 또한 `numOfRows` 상한이 100이므로(1000 요청 시 `LIMITED_OF_DATA_EXCEEDS_ERROR`), 전체 41,080건 수집에 약 411페이지 페이징이 필요하다.

```xml
<item>
  <company>미산식품</company>
  <productGb>식품</productGb>
  <businessitem>C10100016</businessitem>
  <businessitemNm>혼합음료</businessitemNm>
  <businesstypeNm>식품제조가공업</businesstypeNm>
  <area1>경기도</area1>
  <area2>부천시</area2>
</item>
```

- `productGb`: "식품" 또는 "축산물"
- `businessitem`: 개별 품목코드 → 품목코드 API와 조인 키

### 품목코드 API 응답 (1건)

이쪽은 `returnType=json`이 정상 작동한다.

```json
{
  "cd": "C10100016",
  "pcd": "C101",
  "cdnmKr": "혼합음료",
  "useyn": "Y"
}
```

- `cd`: 개별 품목코드 = 인증업체 API의 `businessitem`과 매칭
- `pcd`: 상위 카테고리 코드 → 품목유형으로 변환

## 6. 매핑 정교화 과정

`businessitem` 코드가 단일 코드로 딱 떨어지지 않는 경우가 있어, 단계적으로 매핑 로직을 보강했다.

| 단계 | 처리 대상 | 방법 | 매핑 성공 |
|---|---|---|---|
| 1차 | 표준 `Cxxx` 코드 | `businessitem` → 품목코드 테이블 `pcd` → 품목유형 | 30,513건 |
| 2차 | 콤마 결합 코드 (`86,89`) | 콤마 분리 후 첫 코드로 매핑 | +콤마 케이스 |
| 2차 | 축산물 숫자 코드 (`86`, `87`, `89`) | 숫자 코드 직접 매핑 테이블 추가 | 31,704건 |
| 2차 | 긴 코드 (`C0322020400000` 간편조리세트) | 직접 매핑 테이블 추가 | |
| 3차 | 누락 상위코드 (`C001`, `C002`, `C005`) | pcd 매핑 테이블에 추가 | **31,857건** |

**매핑 로직 우선순위** (`resolve_category` 함수):
1. 콤마로 코드 분리
2. 각 코드에 대해 → 긴 코드 직접 매핑 → 숫자 코드 직접 매핑 → 품목코드 테이블(pcd) → 코드 앞부분 추정 순으로 시도
3. 첫 매칭되는 품목유형 반환

## 8. 매핑 실패 처리 원칙

매핑 실패 9,223건은 **의도적 제외 대상**이다. 오류가 아니라, 분석 범위(식품 제조·가공)에 해당하지 않는 데이터다.

### 제외 사유

식약처 CSV(생산액, 부적합률, 업체 수)는 모두 **식품 제조·가공업체** 기준으로 집계되어 있다. HACCP 인증 데이터도 동일 범위로 맞춰야 Vulnerability 비율이 왜곡되지 않는다.

| 제외 그룹 | 예시 코드 | 건수(대략) | 제외 이유 |
|---|---|---|---|
| 가축 원물 | 한우(69), 돼지(68), 산란계(73), 육계(72), 젖소(70), 닭(76), 오리(74), 메추리(714) | ~7,400 | 살아있는 동물·도축 원료. 가공 전 단계이므로 식품군 분류에 해당 없음. CSV 표에도 대응 행 없음 |
| 판매·유통업 | 식용란수집판매업(581), 식용란선별포장업(901), 식육판매업(176), 축산물유통전문판매업(K00300001) | ~2,355 | 제조가 아닌 유통·판매. 생산액 0, 식약처 제조업체 통계 미포함 |
| 사료 | 섬유질 배합사료(758), 애완동물 배합사료(762) | ~127 | 식품이 아닌 사료 |

### 핵심 논리

"관련 없어서 버린다"가 아니라, **비교 기준(CSV)이 식품 제조업체이므로 HACCP 데이터도 같은 범위로 정렬**한 것이다. 범위가 다르면 분모(전체 업체 수)와 분자(인증 업체 수)의 기준이 어긋나 취약도 지표가 왜곡된다.

## 10. 데이터 정합성 한계 및 처리

### 범위 통일: 식품만 집계 (축산물 제외)

HACCP 인증업체 API에는 식품(23,712건)과 축산물(17,379건)이 모두 포함된다. 그러나 스코어링 기준이 되는 식약처 CSV(1-1-1-2 전체 업체 수, 1-2-1-2 생산액 등)는 **식품제조·가공업 기준** 통계다.

분자(HACCP 인증 수)와 분모(전체 업체 수)의 범위를 맞추기 위해, HACCP 집계 시 `productGb == "식품"`만 포함하고 축산물은 제외한다.

- 이 처리로 식육가공품 인증 수가 7,979 → 205로 감소 (축산물 햄·소시지·양념육 등이 빠지고 식약처 소관 "식육함유가공품"만 남음)
- 축산물 HACCP은 별도 소관·별도 통계 체계이므로, 본 분석은 "식품 제조·가공" 범위로 명시적으로 한정한다

### HACCP 인증률 100% 초과 문제

일부 품목유형(특히 과자류·빵류·떡류)은 HACCP 인증 수가 식품제조가공업체 수를 초과하여 인증률이 100%를 넘는다.

**원인**: 빵·과자류는 식품제조가공업 외에도 **즉석판매제조가공업, 제과점영업** 등 다른 업종에서도 생산되며, 이들 업종도 HACCP 인증을 받는다. 그러나 분모로 쓰는 1-1-1-2(식품제조·가공업체 현황)에는 제조가공업만 집계되어, 타 업종 인증분이 분자에만 반영되면서 100%를 초과한다.

**처리 방식** (본 분석에서 채택):
- 인증률을 100%로 캡(cap) 처리 (`HACCP_인증률` 컬럼)
- 원본값은 `HACCP_인증률_원본` 컬럼에 보존하여 검증 가능하게 유지
- 스코어링 목적상 인증률은 **취약도(Vulnerability)** 산출에 쓰이며, 100% 초과는 "HACCP 보급이 충분함 = 투자 우선순위 낮음"을 의미하므로 캡 처리가 결론을 왜곡하지 않음

**대안 (미채택)**:
- 즉석판매제조가공업(1-1-1-3) 데이터를 분모에 추가하면 더 정확하나, 업종별 HACCP 인증 구분이 API에서 명확히 제공되지 않아 정합이 어려움
- 향후 개선 시 업종 단위 분모 정교화를 검토할 수 있음

### 결측 품목

일부 품목유형은 특정 지표가 결측이다.

| 품목유형 | 결측 지표 | 사유 |
|---|---|---|
| 식품첨가물 | 전체업체수, 감시/위반 | 1-1-1-2 품목 분류에 미포함 (별도 업종) |
| 주류 | 감시/위반 | 1-3-1-1 품목 블록에 미포함 (주류는 국세청 소관 감시) |
| 알가공품류 | 감시/위반 | 1-3-1-1 품목 블록에 데이터 없음 |
| 기타식품류 | 부적합률 | 1-4-3에 대응 행 없음 |

결측은 스코어링 시 해당 변수에서 제외하거나 보수적으로 처리(최소값 대체 등)하며, 최종 스코어 산출 단계에서 처리 방침을 명시한다.

### 문제 A: HACCP 인증률 100% 초과 (1295%, 112%)

**증상**: 초기 조인 결과 식육가공품 인증률 1295%, 과자류 112% 등 비현실적 값 발생.

**진단 과정** (3단계에 걸쳐 원인 규명):

1. **범위 불일치 (분자 > 분모)**
   - 분자(HACCP)는 식품 + 축산물을 모두 집계, 분모(식약처 1-1-1-2)는 식품제조가공업만 집계
   - HACCP 축산물 17,379건이 분자에만 포함되어 식육가공품이 폭증
   - → `productGb == "식품"` 필터 추가 (축산물 제외). 식육가공품 7,979 → 205

2. **업종 불일치**
   - HACCP "식품"에는 식품제조가공업 외 즉석판매제조가공업, 제과점영업, 주류제조 등이 섞임
   - 분모(1-1-1-2)는 식품제조가공업만이므로 분자에 타 업종이 남으면 여전히 초과
   - → `businesstypeNm == "식품제조가공업"` 필터 추가

3. **집계 단위 불일치 (핵심 원인)**
   - 두 통계 모두 "업체 수"가 아니라 "품목군 계상" 방식 (1-1-1-2 원문 주석 명시: *1개 업체가 2개 이상 품목군 생산 시 각각 계상*)
   - 그러나 HACCP API는 한 업체의 여러 품목을 **개별 행**으로 반환 → 과자류에서 4,037행 = 3,245업체로 중복
   - 한 업체가 같은 품목유형 내 여러 품목(과자+빵류+떡류)을 인증받으면 중복 카운트
   - → **(품목유형, 업체명) 쌍으로 중복 제거** 후 집계. 과자류 4,037 → 3,246, 인증률 90.0%로 정상화

**최종 집계 기준** (`aggregate_by_category`):
1. `productGb == "식품"` (축산물 제외)
2. `businesstypeNm == "식품제조가공업"` (타 업종 제외)
3. (품목유형, 업체) 중복 제거 (업체 단위 카운트)

결과: 식품제조가공업 15,909개 업체가 23개 품목유형으로 집계. 인증률 전부 100% 이하(8.1%~90.6%). 캡(cap) 처리 불필요.

> 참고: 10절의 "인증률 100% 캡 처리"는 위 3단계 진단 **이전**의 임시 대응이었다. 근본 원인(집계 단위)을 해결하면서 캡은 불필요해졌으나, 코드에는 안전장치로 남겨두고 `HACCP_인증률_원본` 컬럼도 유지한다.

### 문제 B: 세부행 분할 품목의 값 누락

**증상**: 음료류 검사건수 2,787 (과자류 7,069보다 작음 — 비현실적), 즉석식품류 검사 5건 등.

**원인**: 1-2-1-2와 1-4-3은 일부 품목유형이 세부 품목으로 분할된 구조.
```
당류 Sugars,      설탕류,   236, ...   ← col0=당류, col1=설탕류
"",              당시럽류,  12, ...    ← col0 비어있음, col1=당시럽류
"",              올리고당,  179, ...
...
```
초기 파서가 상위행(col0=당류)의 첫 값만 읽고 이후 세부행(col0 공백)을 누락 → 당류 715 대신 236만 집계.

**해결**: 세부행 합산 공통 파서(`parse_with_subrows`) 작성.
- col0에 품목유형명이 있으면 현재 상위 갱신
- col0가 비어있으면 직전 상위 품목유형에 값 누적
- 값 컬럼은 항상 고정 위치(검사=col2, 부적합=col4, 생산량=col3, 생산액=col4)

결과: 당류 검사 715, 음료류 7,980으로 정상 합산.

## 19. 몬테카를로 민감도 분석 (등급 가중치 근거 문제의 최종 해결)

15절에서 회수등급 가중치(3:2:1)의 정량적 근거 부재를 등급 민감도 4시나리오로 방어했으나, "왜 그 4개 값인가"라는 반박 여지가 남는다. 이를 몬테카를로 방식으로 완전히 해소했다.

### 방식

기존: 가중치 후보(3:2:1, 2:1.5:1, 5:3:1, 1:1:1)를 손으로 지정 → 각각 순위 계산
몬테카를로: 가중치를 무작위로 10,000회 추출 → 매번 순위 재계산 → 순위 **분포** 산출

특정 값을 지정하지 않으므로 "왜 이 값인가"라는 질문 자체가 성립하지 않는다.

### 두 층위 가중치 처리

| 가중치 | 제약 | 근거 |
|---|---|---|
| 변수 (R/S/V/I) | 없음 (Dirichlet 무작위) | 변수 간 우선순위 근거 없음 |
| 등급 (1/2/3) | 순서만 (g1 ≥ g2 ≥ g3) | 식약처 등급 정의상 1등급이 더 위해 |

핵심 구현:
```python
var_w = rng.dirichlet([1,1,1,1])       # 변수: 합=1 무작위
grade_w = np.sort(rng.random(3))[::-1] # 등급: 내림차순 → g1≥g2≥g3 자동
impact = C @ grade_w                    # C: 품목유형 × 등급 건수 행렬
```
스케일 무관성: Impact는 log+min-max를 거치므로 (3,2,1)과 (6,4,2)가 동일 결과. 따라서 무작위 범위 0~1로 충분.

효율: 회수 데이터를 1만 번 재매핑하지 않고, 등급별 건수 행렬(23×3)을 한 번 만들어 행렬곱으로 처리.

### 자율회수·등급공백 처리

회수 377건 중 자율회수 2건·등급 공백 8건은 제외. 공백은 "경미"가 아니라 "심각도 판정 불가"이며(리스테리아 검출 등 심각 사례도 공백에 포함), 3등급으로 취급하면 왜곡되므로 등급이 명확한 1/2/3등급만 사용. 품목유형 매핑까지 거쳐 최종 249건 반영.

### 결과 (N=10,000)

| 품목유형 | 중앙순위 | top5 유지율 | 해석 |
|---|---|---|---|
| 기타식품류 | 2 | 95.6% | 거의 항상 최상위 (단, 이질적 범주 주의) |
| 음료류 | 3 | 93.4% | 매우 안정 |
| 빙과류 | 3 | 65.8% | 위험 중심이면 최우선 |
| 조미식품 | 4 | 70.4% | 안정 |
| 식육가공품 | 5 | 57.1% | 규모 중심이면 최우선 |
| 장류 | 9 | 23.6% | 관점 의존 (취약도 강조 시 1위, 아니면 하위) |
| 유가공품류 | 11 | 30.6% | 관점 의존 (회수 0, 부적합률만 높음) |
| 특수의료용도식품 | 23 | 0.0% | 어떤 가중치에도 최하위 |

**결론**: 빙과류·음료류·기타식품류·조미식품·식육가공품은 가중치와 무관하게 상위권을 유지(강건). 장류·유가공품류는 관점에 따라 크게 변동(정책 목적별 판단 필요). 특정 가중치를 지정하지 않고 순위 안정성을 확률로 입증.

### 발표 문장
> "회수 등급 가중치는 정량적 근거가 없어 특정 값을 지정하지 않았다. 1등급 ≥ 2등급 ≥ 3등급이라는 순서 조건(식약처 등급 정의)만 두고, 변수 가중치를 포함한 모든 가중치를 무작위로 1만 회 추출해 순위를 재계산했다. 빙과류는 65.8%, 음료류는 93.4%의 확률로 상위 5위 안에 들었다."

## 12. 3단계: 스코어링 모델 설계와 변수 확정 과정

3단계는 단순히 점수를 매기는 작업이 아니라, **"어떤 변수를 쓸 수 있는가"를 데이터로 검증하며 모델을 확정**하는 과정이었다. 초기 설계는 야심찼으나, 데이터 현실에 맞춰 여러 차례 축소·조정했다.

### 초기 설계 (팀 논의안)

금융 자본배분 개념을 살려 목적별 지수를 나누는 정교한 모델을 구상했다:

- **SRS (안전 리스크)** = Hazard Density + Recall Intensity + Nonconformity Intensity
- **EES (경제 노출)** = 생산액
- **MC (관리 복잡성)** = CCP Density + 제품계열수
- **CB (비용 부담)** = 심사수수료 / 생산액
- **HIP** = SRS + EES + MC, **HSP** = HIP + CB (비용까지 고려한 정부지원 우선순위)

이 설계는 이론적으로 우수했으나, 각 변수의 데이터 확보 가능성을 검증하며 대폭 조정되었다.

### 변수별 데이터 검증 결과

| 변수 | 필요 데이터 | 검증 결과 | 결론 |
|---|---|---|---|
| 부적합률 (Risk) | 1-4-3 수거검사 | 품목유형별 확보 | ✅ 채택 |
| 생산액 (Scale) | 1-2-1-2 | 품목유형별 확보 | ✅ 채택 |
| 인증률 (Vulnerability) | 인증원 API + 1-1-1-2 | 품목유형별 산출 | ✅ 채택 |
| 회수 (Impact) | I0490 | 품목명 매핑으로 확보 | ✅ 채택 |
| Hazard Density | 위해요소 데이터 | **업종 단위, 식품 23행뿐 (대부분 축산)** | ❌ 불가 |
| CCP Density (MC) | CCP 중요관리점 정보 | **위와 동일 데이터, 품목유형 매핑 불가** | ❌ 불가 |
| CB (비용부담) | 심사수수료 API | **업종 단위, 품목유형 미구분** | ❌ 불가 |

### 핵심 발견: 인증원 데이터의 "업종 단위" 한계

세 변수(Hazard Density, MC, CB)가 모두 동일한 이유로 막혔다. 인증원이 제공하는 위해요소·CCP·심사수수료 데이터는 **업종(식품제조가공업 등) 단위**로만 제공되며, 우리 분석의 기준인 **품목유형(과자류·음료류 등) 단위**로 세분화되지 않는다.

- 심사수수료(`CostListService`): "식품제조가공업" 하나로 23개 품목유형이 뭉뚱그려짐 → 품목유형별 CB 산출 불가
- 위해요소·CCP(중요관리점 정보): 10,527행 중 식품제조가공업은 23행뿐이고, 나머지는 가축사육·식육포장 등 축산물. 그 23행도 품목유형 구분 없음

**CB의 대안 검토와 기각**: CB를 심사수수료 대신 업체규모(1-2-1-8)로 근사하는 방안을 검토했으나, 이 역시 업종 단위이고 "비용 부담"이 아닌 "규모 취약성"으로 의미가 달라져 HIP 내부 변수로는 채택하지 않았다. (단, 정부의 소규모 업체 지원 정책과 연결되는 별도 확장(HSP)의 여지로 남겨둠.)

### 최종 확정: 4변수 HIP

```
HIP = (Risk + Scale + Vulnerability + Impact) / 4
```

데이터가 품목유형 단위로 확보되는 4개 변수로 확정. 못 쓴 변수(Hazard/CCP/CB)는 "데이터 한계"로 명시하고, 이를 **"공공데이터의 품목유형 단위 제공 필요"라는 정책 제언**으로 전환.

## 13. Risk 변수: 부적합률 선택과 소표본 보정

### 부적합률 vs 위반율

Risk 후보로 부적합률(1-4-3 수거검사)과 위반율(1-3-1-1 감시)이 있었다.

| 지표 | 대상 | 측정 | HACCP 관련성 |
|---|---|---|---|
| 부적합률 | 제품 | 실험실 검사 (성분·미생물) | 직접 (공정 관리 결과) |
| 위반율 | 업체 | 현장 점검 (위생·표시) | 간접 (HACCP 범위 밖 포함) |

HACCP은 제조 공정의 위해요소를 관리하는 시스템이므로, "HACCP 투자 → 개선"의 인과가 명확한 **부적합률**을 Risk 주지표로 채택. 위반율은 표시 규정 위반 등 HACCP과 무관한 항목이 섞여 제외.

### 소표본 편향 문제와 베타-이항 축소

부적합률을 그대로 쓰면 검사 건수가 적은 품목이 왜곡된다.

```
빙과류   검사 250건 중 5건 → 2.0%   (표본 작아 불안정)
음료류   검사 7,980건 중 26건 → 0.33% (표본 커서 신뢰)
```

빙과류 2.0%는 우연히 몇 건 더 걸렸을 수 있으나, 단순 비율로는 음료류의 6배로 과대평가된다.

**해결: 베타-이항 축소 (Empirical Bayes shrinkage)**
```
보정 부적합률 = (부적합 + α) / (검사 + α + β)
```
- α, β는 전체 부적합률 분포에서 적률법으로 추정 (임의값 아님)
- 검사 수가 크면 원래 값 유지, 작으면 전체 평균(약 0.28%)으로 축소

**효과**: 벌꿀 1.82%(55건)→0.74%, 빙과류 2.0%(250건)→1.41%로 소표본 과대평가 완화. 음료류·과자류 등 대표본은 거의 불변. 이 보정으로 벌꿀은 회수 순위에서 7위→16위로 조정되었다.

## 14. 정규화 방법: 변수별 차등 적용

모든 변수를 0~1로 맞추되, 변수 특성에 따라 방법을 다르게 적용했다. (최종 범위 0~1 동일 + 방향 일관 조건을 지키면 변수별 다른 정규화는 방법론적으로 문제없음.)

| 변수 | 정규화 | 이유 |
|---|---|---|
| Risk | 베타-이항 축소 → min-max | 소표본 이상치(빙과류) 보정 필요 |
| Scale | log10 → min-max | 생산액 최대/최소 3,418배 편차 완화 |
| Vulnerability | min-max | 원래 0~1 범위라 분포 고름 |
| Impact | log(x+1) → min-max | 회수 편차 극심 (기타식품류 125 vs 대부분 한 자릿수) |

**min-max의 한계 인지**: min-max는 최대·최소 두 값으로 스케일이 정해져 이상치에 취약하다. 이를 Risk는 베타-이항 축소로, Scale·Impact는 log 변환으로 완화했다. 순위(rank) 정규화도 검토했으나 간격 정보를 버리는 단점이 있어, 간격을 보존하면서 이상치를 완화하는 log/축소 방식을 선택했다.

**정규화 점수 해석 주의**: 정규화 결과 1.000은 "100%"나 "절대 최댓값"이 아니라 **"해당 변수에서 23개 중 1위"**를 의미한다. (빙과류 Risk 1.000 = 부적합률 최고, 실제 보정값은 1.41%.) 발표 시 원본값 병기 권장.

## 15. Impact 변수: 회수 데이터 매핑과 등급 가중

### 회수 데이터 매핑 (품목명 기반)

회수 데이터(I0490)의 품목코드(`PRDLST_CD`)는 14자리로 우리 매핑 테이블(8~9자리)과 체계가 달라 직접 매칭이 10/377에 불과했다. 대신 **품목명(`PRDLST_CD_NM`) 키워드 매핑**을 사용:

- 키워드 사전으로 23개 품목유형에 매핑 (예: "고춧가루"→조미식품, "떡류"→과자류)
- 제외 키워드로 분석 대상 밖 처리 (건강기능식품, 기구용기포장, 주류, 농산물 원물)
- 결과: 377건 중 257건 매핑, 120건 제외 (제외분은 전부 우리 23개 밖의 정당한 대상)

초기 매핑에서 벌집꿀·샤베트·식용얼음·체중조절식품 등이 누락되어 키워드를 보강했다 (벌꿀 Impact 0→정상화).

### 회수등급 가중과 근거 문제

회수는 심각도(1·2·3등급)가 다르므로 단순 건수보다 **등급 가중**이 적절하다.
```
Impact = Σ(회수건수 × 등급가중치)
```

**등급 가중치의 근거 확인**: 식약처 고시를 검토한 결과, 회수등급은 위해 심각도 순서(1>2>3)로 **법적으로 정의**되어 있으나, "3:2:1" 같은 **정량적 가중치 비율은 규정되어 있지 않다**. (등급별 회수 완료 기한 차등은 있으나 지침마다 수치가 달라 직접 근거로 삼기 부적절.)

**해결: 등급 가중치를 민감도 분석 대상에 포함**. 3:2:1을 기본으로 2:1.5:1, 5:3:1, 1:1:1(단순건수) 4버전을 생성하고 순위 변동을 비교. 결과적으로 **거의 전 품목이 ±0~1로 안정**하여, 등급 가중치 선택이 결론에 영향을 주지 않음을 입증했다. 이로써 "3:2:1 근거 부재" 문제를 정면 해소.

### 4변수 HIP 최종 순위 (상위)

1위 빙과류, 2위 기타식품류, 3위 음료류, 4위 식육가공품, 5위 조미식품

**민감도 1 (변수 가중치)**: Risk/Scale/Vuln/Impact 중 하나를 강조(0.4)해도 상위권(빙과류·기타식품류·음료류) 안정. 유가공품류·장류는 관점에 따라 변동(회수 0, 취약도 편중의 영향).

두 민감도 모두 "특정 가중치 선택에 의존하지 않는 강건한 결론"을 뒷받침한다.

## 17. 프로젝트의 정책적 위치

분석 배경으로 정부 현황을 확인한 결과, 본 프로젝트의 기여가 명확해졌다.

**정부 현행 (팩트):**
- HACCP 의무적용을 전 업체로 단계적 확대 중 (소규모는 부담으로 지체)
- 시설개선자금 연 39억, 개보수 50% 국고 지원

**정부 방식의 맹점:**
- "어느 식품군이 시급한가"라는 축이 없음
- 이미 인증율 포화된 식품군과 위험·취약한 식품군이 동일 취급 → 예산 비효율

**본 프로젝트의 기여:**
- 정부 기준(업체 규모)을 부정하지 않고, **식품군 우선순위** 축을 데이터로 추가
- "취약한 식품군의 소규모 업체 우선" 이라는 결합 배분으로 정교화
- 못 쓴 데이터(위해요소·CCP·수수료의 업종 단위 한계)는 **공공데이터 품목유형 단위 제공**이라는 정책 제언으로 전환

## 19. 몬테카를로 민감도 분석 (등급 가중치 근거 문제의 최종 해결)

15절에서 회수등급 가중치(3:2:1)의 정량적 근거 부재를 등급 민감도 4시나리오로 방어했으나, "왜 그 4개 값인가"라는 반박 여지가 남는다. 이를 몬테카를로 방식으로 완전히 해소했다.

### 방식

기존: 가중치 후보(3:2:1, 2:1.5:1, 5:3:1, 1:1:1)를 손으로 지정 → 각각 순위 계산
몬테카를로: 가중치를 무작위로 10,000회 추출 → 매번 순위 재계산 → 순위 **분포** 산출

특정 값을 지정하지 않으므로 "왜 이 값인가"라는 질문 자체가 성립하지 않는다.

### 두 층위 가중치 처리

| 가중치 | 제약 | 근거 |
|---|---|---|
| 변수 (R/S/V/I) | 없음 (Dirichlet 무작위) | 변수 간 우선순위 근거 없음 |
| 등급 (1/2/3) | 순서만 (g1 ≥ g2 ≥ g3) | 식약처 등급 정의상 1등급이 더 위해 |

핵심 구현:
```python
var_w = rng.dirichlet([1,1,1,1])       # 변수: 합=1 무작위
grade_w = np.sort(rng.random(3))[::-1] # 등급: 내림차순 → g1≥g2≥g3 자동
impact = C @ grade_w                    # C: 품목유형 × 등급 건수 행렬
```
스케일 무관성: Impact는 log+min-max를 거치므로 (3,2,1)과 (6,4,2)가 동일 결과. 따라서 무작위 범위 0~1로 충분.

효율: 회수 데이터를 1만 번 재매핑하지 않고, 등급별 건수 행렬(23×3)을 한 번 만들어 행렬곱으로 처리.

### 자율회수·등급공백 처리

회수 377건 중 자율회수 2건·등급 공백 8건은 제외. 공백은 "경미"가 아니라 "심각도 판정 불가"이며(리스테리아 검출 등 심각 사례도 공백에 포함), 3등급으로 취급하면 왜곡되므로 등급이 명확한 1/2/3등급만 사용. 품목유형 매핑까지 거쳐 최종 249건 반영.

### 결과 (N=10,000)

| 품목유형 | 중앙순위 | top5 유지율 | 해석 |
|---|---|---|---|
| 기타식품류 | 2 | 95.6% | 거의 항상 최상위 (단, 이질적 범주 주의) |
| 음료류 | 3 | 93.4% | 매우 안정 |
| 빙과류 | 3 | 65.8% | 위험 중심이면 최우선 |
| 조미식품 | 4 | 70.4% | 안정 |
| 식육가공품 | 5 | 57.1% | 규모 중심이면 최우선 |
| 장류 | 9 | 23.6% | 관점 의존 (취약도 강조 시 1위, 아니면 하위) |
| 유가공품류 | 11 | 30.6% | 관점 의존 (회수 0, 부적합률만 높음) |

### 고민 1: 정규화 방법의 시각적 근거 (fig0 EDA)

변수마다 정규화를 다르게 적용한 근거를 EDA로 시각화했다.

- **부적합률**: 빙과류 2.0% 단일 극단값 존재 → min-max 시 지배 위험 → 베타-이항 축소 필요
- **생산액**: 최대/최소 3,418배 편차, 좌측 집중 → log 변환 후 고른 분포 (변환 전후 히스토그램 병치로 근거 제시)
- **인증율**: 8~91% 고르게 분포 → 추가 변환 없이 min-max
- **회수**: 기타식품류 125 vs 다수 0으로 치우침 → log(x+1) 변환

"왜 변수마다 다르게 처리했는가"를 데이터 분포로 직접 보여주어, 방법론 선택의 자의성 논란을 차단했다.

### 고민 2: 포트폴리오 매트릭스 기준선 (fig4)

위험-규모 4분면 매트릭스에서 기준선을 어디에 둘지가 쟁점이었다.

**문제**: 일반적으로 정규화 값 0.5를 기준선으로 쓰나, 본 데이터는 부적합률이 극단적으로 치우쳐(빙과류만 1.0, 나머지 0.0~0.4) 0.5 기준 시 23개 중 16개가 ③사분면(저위험·대규모)에 집중되어 매트릭스의 변별력이 상실된다.

**검토한 대안**:
- 0.5 고정: 일반적이나 편중 발생 (분면 분포 2/1/16/4)
- 중앙값 기준: 분포 반영, 고르게 분할 (분면 분포 6/6/6/5)
- 도메인 임계값: 부적합률·인증율의 법적 위험 기준이 있으면 최선이나, 확인 결과 품목유형 단위 임계값 부재

**처리**: 0.5와 중앙값 두 기준을 **좌우 패널로 병치**하고, 각 분면의 식품군 개수를 함께 표기. 두 기준 모두에서 빙과류가 ①사분면(고위험·대규모)에 위치함을 확인. 이는 등급 가중치 민감도 분석과 동일한 논리 — "기준을 바꿔도 결론이 동일함을 입증".

> 중앙값 기준선은 HIP 순위 산출과 무관한 **해석용 보조선**이며, 순위 자체는 정규화된 4변수 가중합으로 결정되므로 기준선 선택에 영향받지 않는다.

### 고민 3: 예산 배분 시뮬레이션의 "현행 방식" 정의 (fig5)

HIP 기반 차등 배분의 효과를 보이기 위해 균등 배분과 비교했다.

**주의점**: 정부 현행 지원은 업체 규모(매출 5억 미만)와 신청 순서(선착순) 기준이며, 엄밀히는 균등 배분이 아니다. 그러나 **식품군별 우선순위 개념이 없다**는 점에서 "식품군 구분 없는 배분"으로 간주하고, 비교 기준선으로 균등 배분을 설정했다.

**결과**: 총 예산 100 기준, 재배분 규모는 14.3% (상위군으로 이동). 빙과류(+2.5), 기타식품류(+2.3), 음료류(+1.9)가 증가하고, 특수의료용도식품(−2.9), 면류(−2.0)가 감소. "이미 포화된 식품군의 예산을 취약·고위험 식품군으로 이동"이라는 정책 메시지를 정량화.

## 19. 몬테카를로 민감도 분석 (등급 가중치 근거 문제의 최종 해결)

15절에서 회수등급 가중치(3:2:1)의 정량적 근거 부재를 등급 민감도 4시나리오로 방어했으나, "왜 그 4개 값인가"라는 반박 여지가 남는다. 이를 몬테카를로 방식으로 완전히 해소했다.

### 방식

기존: 가중치 후보(3:2:1, 2:1.5:1, 5:3:1, 1:1:1)를 손으로 지정 → 각각 순위 계산
몬테카를로: 가중치를 무작위로 10,000회 추출 → 매번 순위 재계산 → 순위 **분포** 산출

특정 값을 지정하지 않으므로 "왜 이 값인가"라는 질문 자체가 성립하지 않는다.

### 두 층위 가중치 처리

| 가중치 | 제약 | 근거 |
|---|---|---|
| 변수 (R/S/V/I) | 없음 (Dirichlet 무작위) | 변수 간 우선순위 근거 없음 |
| 등급 (1/2/3) | 순서만 (g1 ≥ g2 ≥ g3) | 식약처 등급 정의상 1등급이 더 위해 |

핵심 구현:
```python
var_w = rng.dirichlet([1,1,1,1])       # 변수: 합=1 무작위
grade_w = np.sort(rng.random(3))[::-1] # 등급: 내림차순 → g1≥g2≥g3 자동
impact = C @ grade_w                    # C: 품목유형 × 등급 건수 행렬
```
스케일 무관성: Impact는 log+min-max를 거치므로 (3,2,1)과 (6,4,2)가 동일 결과. 따라서 무작위 범위 0~1로 충분.

효율: 회수 데이터를 1만 번 재매핑하지 않고, 등급별 건수 행렬(23×3)을 한 번 만들어 행렬곱으로 처리.

### 자율회수·등급공백 처리

회수 377건 중 자율회수 2건·등급 공백 8건은 제외. 공백은 "경미"가 아니라 "심각도 판정 불가"이며(리스테리아 검출 등 심각 사례도 공백에 포함), 3등급으로 취급하면 왜곡되므로 등급이 명확한 1/2/3등급만 사용. 품목유형 매핑까지 거쳐 최종 249건 반영.

## 20. 적용공백 재정의와 분석 범위 축소 (20개)

### 문제 제기

식품공학 검토 결과, Vulnerability(1 − HACCP 인증률)를 "관리 취약도"로 해석하는 것이 부적절하다는 지적이 제기되었다. HACCP 미인증은 관리 부실이 아니라 **법적 의무 대상이 아니어서 인증받지 않은 경우**를 포함하기 때문이다.

데이터로 확인한 결과 실제로 편향이 존재했다.

| 적용구분 | 식품군 수 | 평균 인증률 |
|---|---|---|
| 대부분 의무 | 7 | 69.8% |
| 일부 의무 | 3 | 39.5% |
| 품목 의무 없음 | 10 | 21.7% |

즉 기존 Vulnerability는 상당 부분 "의무 여부"를 측정하고 있었다.

### 조치 1: 축산 3개 제외 (23 → 20개)

식육가공품·유가공품류·알가공품류는 「축산물 위생관리법」 제9조 이하가 근거로, 「식품위생법」 제48조 체계와 의무 적용의 법적 기반이 다르다. 두 체계를 함께 비교하면 인증률의 의미가 달라지므로 분석 범위에서 제외했다.

### 조치 2: 변수명·의미 변경

Vulnerability → **적용공백**. "HACCP 인증으로 관리되는 범위가 상대적으로 작다"는 의미이며, 관리 부실을 뜻하지 않는다.

### 조치 3: 적용구분 라벨 (해석 전용)

식품위생법 시행규칙 제62조 기준으로 20개 식품군에 라벨 부여. **점수·순위·2×2 분류 어디에도 사용하지 않고**, 적용공백이 큰 이유를 설명할 때만 사용한다.

**조문 대조 결과 (시행규칙 제62조 제1항, [시행 2026.9.1] 총리령 제2150호)**

| 적용구분 | 식품군 | 근거 호 |
|---|---|---|
| 대부분 의무 (5) | 과자류·빵류·떡류 | 제4호 (과자·캔디류·빵류·떡류) |
| | 음료류 | 제6호 (다류·커피류 제외) |
| | 면류 | 제10호 (유탕면·생면·숙면·건면) |
| | 특수영양식품 | 제11호 |
| | 특수의료용도식품 | 제11의2호 |
| 일부 의무 (5) | 빙과류 | 제5호 (빙과류 중 '빙과'만) |
| | 코코아가공품류 또는 초콜릿류 | 제9호 ('초콜릿류'만) |
| | 수산가공식품류 | 제1호(어묵·어육소시지), 제2호(냉동 어류·연체류·조미가공품) |

"100억 기준 적용"의 정식 표기는 **"품목별 의무대상은 아니나, 전년도 총매출액 100억 원 이상인 식품제조·가공업 영업소에서 제조·가공하는 경우 HACCP 적용 대상이 되는 식품군"**이다. "비의무"라는 표현은 사용하지 않는다.

**각주**
1. 제3호(냉동식품 중 피자류·만두류·면류)와 제7호(레토르트식품)는 본 분석의 20개 식품군과 1:1 대응하지 않는 별도의 HACCP 의무대상 범주이므로, 식품군별 의무 여부를 단순 비교할 때에는 별도로 고려한다.
2. 제13호는 모든 식품군에 공통 적용되나, 업종별 대형 업체 비중에 따라 실질 의무 범위는 상이할 수 있다.
3. 빙과류의 업체 수 통계에는 축산물 소관 아이스크림류 제조업체가 포함되었을 수 있어 적용공백이 과대 산출될 가능성이 있다. 다만 회수 사례는 빙과·샤베트·식용얼음으로 축산물 품목은 확인되지 않았다.

### 조치 4: 2×2 처방 분류

순위(HIP·SMAA)가 "어디부터"에 답한다면, 2×2는 "무엇을"에 답한다. 합산 점수는 왜 높은지를 숨기므로, 같은 순위라도 필요한 정책 수단이 다를 수 있다.

- 가로 = 적용공백, 세로 = 부적합률(Risk), 기준선 = 각 축 20개 중앙값
- 원 크기 = 회수 건수 (칸 결정에 미사용, 중앙값 이상이면 해석 시 병기)

| 분류 | 조건 | 의미와 검토 방향 |
|---|---|---|
| ① 우선 지원·관리 검토 | 인증 낮음 + 부적합 높음 | HACCP 기술지원·교육·도입 지원 등을 우선 검토 |
| ② 현황 모니터링 | 인증 낮음 + 부적합 낮음 | 낮은 인증 수준만으로 관리 부실을 판단하지 않고 현황을 지속 모니터링 |
| ③ HACCP 운영·관리 실효성 추가 점검 | 인증 높음 + 부적합 높음 | HACCP 적용 확대만으로 충분한지 검토하고, 인증 후 사후관리·현장 운영 및 비인증 영역 등을 포함한 추가 점검 검토 |
| ④ 현 수준 유지·지속 모니터링 | 인증 높음 + 부적합 낮음 | 현 관리 수준을 유지하면서 지속적인 모니터링 |

③의 취지는 "인증이 있는데 왜 관리가 안 되는가"가 아니라 **"인증 수준이 높은데도 검사상 부적합 발생 수준이 높은 이유가 무엇인가"**이며, HACCP 확대만으로 충분한지 추가 검토가 필요한 식품군을 의미한다.

**축 구성**
- 가로: 적용공백 (1 − HACCP 인증률) — 오른쪽으로 갈수록 적용 범위 좁음
- 세로: 부적합률 (Risk) — 위로 갈수록 검사상 부적합 발생 높음
- 기준선: 각 축 20개 식품군의 중앙값
- 원 크기: 회수 건수 (칸 결정에 미사용)

**필수 주석**
> 본 분류는 식품군 단위의 HACCP 인증 수준과 검사상 부적합 발생 수준을 활용한 1차 선별 결과이며, HACCP 운영 적정성 또는 개별 업체의 안전관리 수준을 직접 평가하는 것은 아니다.

방법론적으로는 중요도-성과 분석(IPA, Martilla & James 1977)의 사분면 구조를 따른다. 단, 리스크 매트릭스의 범주를 자원 배분 근거로 삼아서는 안 된다는 지적(Cox 2008)에 따라 **순위·예산 배분에는 사용하지 않고 해석 보조로만** 사용한다.

③ 해석 시 주의: 본 데이터는 식품군 단위 집계이므로 부적합·회수가 인증업체와 미인증업체 중 어디에서 발생했는지 구분할 수 없다. "인증업체의 관리 실패"로 단정해서는 안 된다.

## 21. SMAA 전환과 Impact 처리 방식 재검토

### 몬테카를로 → SMAA

가중치를 무작위 추출해 순위 분포를 얻는 방식은 SMAA(Stochastic Multicriteria Acceptability Analysis, Lahdelma et al. 1998)라는 기존 방법론에 해당한다. 방법론의 표준 결과물은 순위 수용성 지수(각 대안이 특정 순위를 차지할 확률)이므로, 보고 지표를 다음과 같이 확정했다(결과 산출 전 확정).

- **핵심**: top5 유지율 (순위 수용성 지수의 누적형)
- **대표값**: 중앙 순위 (극단값에 강건)
- **동점 정리**: 평균 순위 (중앙값이 정수라 동점 빈발)

### Impact 처리 방식 문제 4가지

| # | 문제 | 확인된 사실 |
|---|---|---|
| 1 | 기준 시점 불일치 | 구조 지표는 2024년, 회수는 2013~2026년 누적 |
| 2 | 반영 기간 불균등 | 전체의 71.7%가 2025년 이후. 기타식품류만 29%, 다수 식품군은 100% |
| 3 | 중복 계산 | 동일 사건이 제품별 복수 등록. 전체 23%, 절임·조림류 55% |
| 4 | 회수 경로 불명 | I0490에 촉발 경로(정부 수거·검사/자가품질검사/민원) 항목 없음 |

2015~2023년 9년간 수록 건수가 14건에 불과해, 이는 "해당 기간 회수가 없었다"기보다 **수록 편차**로 보는 것이 타당하다. 따라서 전체 누적 사용 시 "13년간 발생량"이 아니라 "자료 수록량"을 측정하게 된다.

### 조치: Impact를 2024년 이후 + 중복 제거로 변경

- **기간**: 2024년 이후로 제한 → 구조 지표(2024년)와 시작점 일치, 수록 편차 구간 배제
- **중복**: 같은 업체·같은 등록일·같은 사유(앞 12자) = 1건으로 집계
- 결과: 237건 → 156건 (20개 식품군 기준)

시간 관계는 "2024년 구조 → 2024년 이후 회수 발생"의 전향적 관측이 되나, **인과 추론이 아닌 동시대 상관 관측**으로만 해석한다. 구조 지표의 상대적 순서가 관측 기간 동안 유지된다는 가정이 필요하며(정규화 사용으로 값 자체가 아닌 순서만 요구), 2026년은 9월까지의 부분 연도임을 명시한다.

경로 불명(#4)은 Impact 값·순위에는 영향이 없고, Risk와 Impact를 비교 해석할 때만 제약이 된다. "정부 검사가 부족하다"는 식의 결론은 도출할 수 없다. → 공공데이터 개선 제언으로 전환.

### 검증 결과 (N=10,000)

**검증 1 — 가중치 무작위**: 음료류 top5 99.1%, 기타식품류 94.9%, 조미식품 89.7%

**검증 2 — 적용공백 포함/제외**
- 적용공백 무관 12개: 위해·규모 기반으로 상위, 결론 견고
- 적용공백 의존 4개(장류·벌꿀·당류·동물성): 적용공백 제외 시 순위 하락. 장류는 top5 35.0% → 3.5%
- 적용공백에 눌림 4개(과자류·빙과류·특수영양·면류): 인증률이 높아 순위가 낮게 산출. 과자류는 top5 7.9% → 52.7%

이는 "인증률만으로 우선순위를 판단할 수 없다"는 문제 제기를 데이터로 확인한 결과다.

**검증 3 — Impact 처리 방식 3버전**

| 버전 | 기간 | 중복 | 건수 |
|---|---|---|---|
| 주 분석 | 2024~ | 제거 | 156 |
| 민감도 A | 2024~ | 포함 | 187 |
| 민감도 B | 전체 누적 | 제거 | 186 |

**세 버전의 상위 5개가 완전히 일치**(음료류·조미식품·기타식품류·농산가공식품류·빙과류). 기간 설정과 중복 처리 방식이 결론을 좌우하지 않음을 확인했다.

단, 절임류 또는 조림류는 중복률이 55%로 높아 top5 유지율이 0.2~21.1%로 버전 간 편차가 크다. 해석 시 주의를 요한다.

### 장류 해석

장류는 부적합률(0.007, 최저)과 회수(9건, 상위권)가 상반된 양상을 보인다. 단일 원인으로 설명하기보다 다음이 복합 작용한 결과로 해석한다.

① 구조 지표와 회수 자료의 측정 시점이 완전히 일치하지 않는 점
② 회수가 2025년 이후 및 3-MCPD 관련 사례에 집중된 점(13건 중 11건)
③ 동일 사건이 제품별 복수 레코드로 등록되는 점(13건 → 중복 제거 시 9건)
④ 회수가 정부 수거·검사뿐 아니라 자가품질검사 등 다양한 경로로 발생하는 점

이는 오류가 아니라 **단일 지표로 식품군의 안전관리 필요성을 판단하기 어렵다는 본 분석의 전제를 뒷받침하는 사례**다.

## 22. 의무적용 확대 검토와 3-MCPD 사례

### 의무화 확대 후보 판정 원칙

"회수가 많다 → HACCP 의무화"는 성립하지 않는다. 회수 건수는 식품군 규모의 영향을 받으므로(Scale–Impact 순위상관 0.58) 1차 신호로만 사용하고, Risk와 함께 판단한다.

판정은 별도 규칙을 만들지 않고 **2×2의 ①칸 ∩ 100억 기준 적용 식품군**으로 정의한다. ①칸이 이미 "인증 낮음 + 부적합 높음" 조건이므로 중복 규칙을 피할 수 있다.

- Impact 높음 + Risk 높음 → 의무적용 확대의 타당성을 추가 검토할 후보군
- Impact 높음 + Risk 낮음 → 의무화 확대보다 회수 원인 및 발생경로에 대한 추가 검토 필요

### 세부 품목 단위 검토 — 장류만 가능

제62조가 식품군 전체가 아니라 특정 품목을 지정하는 구조이므로(예: 절임·조림류 중 김치, 음료류 중 다류·커피류 제외), 의무화 확대 제언도 세부 품목 단위여야 한다. 회수 자료(2024년 이후·중복 제거)의 세부 품목 분포를 확인했다.

| 식품군 | 회수 | 세부 품목 분포 | 지목 가능 |
|---|---|---|---|
| 장류 | 9건 | 혼합간장 5, 산분해간장 3, 혼합장 1 — **간장 계열 8/9** | 가능 |
| 조미식품 | 21건 | 소스 4, 천연향신료 4, 고춧가루 3, 조미건어포 3 외 7종 — 11개 품목 분산 | 불가 |
| 농산가공식품류 | 20건 | 과채가공 7, 견과류가공 4, 곡류가공 3 외 4종 — 7개 품목 분산 | 불가 |

따라서 제언은 다음과 같이 한정한다.

> 장류는 간장 계열에 9건 중 8건이 집중되어 세부 품목 단위 검토가 가능하나, 조미식품류와 농산가공식품류는 회수가 세부 품목 전반에 분산되어 특정 품목을 의무적용 확대 후보로 지목할 근거가 확인되지 않았다.

**한계**: 회수 자료는 세부 품목까지 제공되나 부적합률·생산액·인증률은 품목유형 단위 자료다. 따라서 세부 품목 수준에서는 Risk와 함께 보는 판정을 적용할 수 없고, 회수 집중도만 확인 가능하다.

### 3-MCPD 사례 (장류)

장류 회수 9건 중 8건이 3-MCPD 기준 초과이며, 세부 품목은 전부 혼합간장·산분해간장 계열이다. 된장·고추장·청국장에서는 확인되지 않았다.

3-MCPD는 산분해 간장 제조공정에서 생성될 수 있는 **공정오염물질**로, HACCP의 **화학적 위해요소(C)**에 해당한다. HACCP이 3-MCPD를 직접 검사해 제거하는 것이 아니라, 생성·혼입 원인과 공정을 위해요소로 분석하고 중요관리점을 설정해 예방·저감하는 방식으로 관리된다. Codex는 산분해 식물성 단백질 관련 3-MCPD 저감 실행규범(CXC 64-2008)을 별도로 두고 있다.

**해석 원칙**
- "장류 HACCP이 3-MCPD를 관리하지 못한다" → 사용 불가 (인증업체 관리 부실로 해석 금지)
- "장류 전체에 HACCP을 확대하면 해결된다" → 사용 불가 (된장·고추장은 해당 없음)
- 적절한 수위: "장류 중 산분해 공정을 포함하는 간장류 제품에 대해, 화학적 위해요소 분석 및 원료·공정조건 관리·검증 등에 관한 기술지원 필요성을 검토할 수 있다"

### 기준 시점 관련 입장

구조 지표(2024년)와 회수(2024~2026년)의 시점 차이에 대해, 본 지수는 **구조 지표가 관측 기간 동안 유지됨을 전제한 예측 모형이 아니라, 기준 시점이 각각 명시된 복수 지표를 종합한 우선순위 지수**로 정의한다. 신용평가지표가 현재 재무상태와 과거 연체 이력을 함께 반영하되 둘 사이의 인과를 주장하지 않는 것과 같은 구조다. 기간 설정의 영향은 Impact 3버전 민감도(21절)로 확인했다.
